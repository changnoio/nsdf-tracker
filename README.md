# NSDF · ระบบติดตามแผนงาน ปีงบประมาณ 2570

แดชบอร์ดภาษาไทยสำหรับผู้จัดการกองทุนพัฒนาการกีฬาแห่งชาติ ใช้ติดตามการจัดสรรงบประมาณและ MOU ของแผนงานที่ 1–5 และติดตามงานจัดซื้อจัดจ้างรายโครงการของแผนงานที่ 9 มีเทมเพลต Excel 6 ไฟล์สำหรับนำเข้ารายสัปดาห์ พร้อมรายงานส่งออกและการเรียกดูรอบย้อนหลัง

## นำโปรเจกต์ขึ้น GitHub

ชุดนี้มีข้อมูลจริงจากรอบวันที่ 9 พฤศจิกายน 2569 รวมยอดงบประมาณและชื่อเจ้าหน้าที่ผู้รับผิดชอบ เลือก **Private** เมื่อสร้าง repository สำหรับงานภายใน

1. สร้าง repository เปล่าบน GitHub เช่น `nsdf-tracker` แล้วใช้ GitHub Desktop เลือก **File → Clone repository** เพื่อเปิดสำเนาบนเครื่อง
2. แตกไฟล์ ZIP ลงในโฟลเดอร์ที่ clone ให้ `README.md`, `package.json`, `dist/` และ `.github/` อยู่ที่รากของ repository รวมไฟล์ที่ขึ้นต้นด้วยจุด เช่น `.gitignore` ด้วย
3. ที่แท็บ **Changes** ตรวจรายการไฟล์ กรอกข้อความ commit แล้วกด **Commit** และ **Push origin** เมื่อเสร็จแล้วจะเห็นซอร์ส แอสเซ็ต และแม่แบบครบในหน้า repository

## ใช้งานระบบเต็ม

ใช้ Node.js 24 ขึ้นไป เปิด terminal ในโฟลเดอร์โปรเจกต์แล้วรัน

```sh
node server.mjs
```

เปิด [แดชบอร์ดบนเครื่อง](http://127.0.0.1:4190/) หรือบน Windows ดับเบิลคลิก `เปิดแดชบอร์ด.cmd` ได้ ชุดนี้รวมไลบรารีฝั่งหน้าเว็บ ฟอนต์ Kanit ภาพ และโลโก้ไว้แล้ว ใช้คำสั่ง `npm start` ได้เช่นกัน

เซิร์ฟเวอร์รับการเชื่อมต่อที่ `127.0.0.1` และเก็บรอบที่นำเข้าใน `.local-data/weekly.sqlite` ทุกหน้าต่างที่เปิดเซิร์ฟเวอร์เดียวกันใช้ประวัติชุดเดียวกัน ตั้ง `NSDF_PORT` เพื่อเลือกพอร์ต หรือ `NSDF_DATA_DIR` เพื่อเลือกโฟลเดอร์เก็บฐานข้อมูลถาวร หากย้ายเครื่อง ให้ปิดเซิร์ฟเวอร์ก่อนคัดลอกโฟลเดอร์ข้อมูลทั้งโฟลเดอร์

## เปิดหน้าเว็บผ่าน GitHub Pages

GitHub Pages ให้บริการหน้าเว็บแบบสแตติก รุ่นนี้แสดงข้อมูลตั้งต้นและใช้นำเข้า Excel ดูรอบย้อนหลัง และส่งออกได้ โดยรอบที่นำเข้าเก็บในเบราว์เซอร์ของผู้ใช้แต่ละคน สำหรับการใช้ประวัติกลางให้ใช้รุ่น Node.js และ SQLite ข้างต้น [ลักษณะบริการของ GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

1. ตรวจสิทธิ์ผู้เข้าชมเว็บไซต์ที่องค์กรต้องการก่อนเผยแพร่ เพราะไฟล์ที่เสิร์ฟให้ผู้ชมรวมข้อมูลตั้งต้นและรายชื่อเจ้าหน้าที่ การเข้าถึง Pages ขึ้นกับแผนบัญชีและการตั้งค่าเว็บไซต์
2. ใน repository ไปที่ **Settings → Pages → Build and deployment** แล้วเลือก **GitHub Actions** เป็น Source
3. ไปที่ **Actions → Publish dashboard to GitHub Pages → Run workflow** เลือก branch ที่มีโปรเจกต์ แล้วสั่งรัน
4. เมื่อขั้นตอน `deploy` สำเร็จ เปิด URL ใน environment `github-pages` เมื่อต้องการเผยแพร่ฉบับปรับปรุงให้สั่ง workflow อีกครั้ง

ทดสอบการสร้างหน้าเว็บบนเครื่องด้วย `node scripts/build-pages.mjs` ไฟล์สำหรับเสิร์ฟจะอยู่ใน `_site/` และรองรับการวางใต้เส้นทางชื่อ repository [คู่มือ workflow ของ GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## อัปเดตประจำสัปดาห์

เปิด **นำเข้าและเทมเพลต** เลือกแผนงาน ดาวน์โหลดแม่แบบแล้วกรอกช่องที่เปลี่ยนตามรหัสรายการเดิม เลือกวันที่รายงานและไฟล์ ตรวจค่าเดิมกับค่าใหม่ แล้วกด **ยืนยันบันทึกรอบรายงาน** ดูผลใน **รายงานรายสัปดาห์** หรือดาวน์โหลด Excel จากหน้ารายแผน

| ตำแหน่ง | สิ่งที่เก็บ |
| --- | --- |
| `dist/` | หน้าแดชบอร์ด การคำนวณ การนำเข้าและส่งออก |
| `dist/data.js` | ข้อมูลฐานที่แปลงจากทะเบียน Excel พร้อมข้อมูลอ้างอิงชีตและแถว |
| `dist/templates/` | แม่แบบแผน 1–5 และ 9 |
| `dist/assets/` | โลโก้ ภาพ ฟอนต์ และไฟล์สิทธิ์ของส่วนประกอบ |
| `server.mjs`, `api.mjs`, `drizzle/` | เซิร์ฟเวอร์ การตรวจข้อมูล และโครงสร้างฐานข้อมูล |
| `worker.mjs`, `build.mjs` | ซอร์สและคำสั่งสร้าง Worker สำหรับสภาพแวดล้อมที่มีฐาน D1 ชื่อ `DB` |

ไฟล์ Excel ต้นทางเก็บแยกจากชุดซอร์ส ข้อมูลที่แดชบอร์ดต้องใช้มีอยู่แล้วใน `dist/data.js` ส่วนประวัติที่เพิ่มภายหลังอยู่ในพื้นที่เก็บข้อมูลของโหมดที่ใช้งาน
